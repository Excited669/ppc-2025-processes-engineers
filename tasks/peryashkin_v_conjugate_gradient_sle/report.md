## 1. Введение

Цель работы — реализовать последовательную и параллельную (MPI) версии метода сопряжённых градиентов (Conjugate Gradient, CG) для решения системы линейных алгебраических уравнений вида `A*x = b`.

Также подготовлены функциональные тесты для проверки корректности решения и тесты производительности для сравнения SEQ и MPI реализаций.

## 2. Постановка задачи

Дана система линейных уравнений:

- `A*x = b`, где `A` — вещественная симметричная положительно определённая матрица (SPD).
- Требуется найти вектор `x` с точностью `eps`.

Входные данные: пара `(N, V)`:
- `N` — размер матрицы `N x N`
- `V` — вариант матрицы (`0`, `1` или `2`)

Выходные данные: вектор решения `x` размера `N`.

Вектор `b` (правая часть) задаётся как `b[i] = 1.0`.

### Варианты матрицы A

**Variant 0 (трёхдиагональная):**
- `A[i,i] = 4`
- `A[i,i-1] = 1` при `i > 0`
- `A[i,i+1] = 1` при `i < N-1`

**Variant 1 (диагональная):**
- `A[i,i] = 5`
- остальные элементы `0`

**Variant 2 (центросимметричная):**
- `A[i,i] = 3`
- `A[i, N-1-i] = -1` если `N-1-i != i`
- остальные элементы `0`

## 3. Базовый алгоритм (SEQ)

Метод CG — итерационный алгоритм для SPD матриц. Используются:
- `r` — невязка (residual)
- `p` — направление поиска (search direction)

Инициализация:
- `x0 = 0`
- `r0 = b - A*x0`
- `p0 = r0`

Итерации (k = 0..):
1) alpha = (r·r) / (p·(A*p))
2) x = x + alpha*p
3) r = r - alpha*(A*p)
4) beta = (r_new·r_new) / (r_old·r_old)
5) p = r + beta*p

Остановка:
- если `sqrt(r·r) < eps`, либо достигнут лимит итераций.

Параметры реализации:
- `eps = 1e-7`
- `max_iters = max(2000, 2*N)`

## 4. Схема распараллеливания (MPI)

Параллельная версия использует разбиение по строкам (block row distribution):

- Каждый процесс получает непрерывный блок индексов `[start, start+local_rows)`.
- Хранятся локальные части `x`, `r`, `p`.
- Скалярные произведения считаются локально и суммируются через `MPI_Allreduce`.

Главное место, где нужны коммуникации — вычисление `A*p`.

### 4.1 Вычисление A*p в MPI

**Variant 1 (диагональная)**  
Коммуникации не нужны:
- `(A*p)[i] = 5*p[i]` для локальных `i`.

**Variant 0 (трёхдиагональная)**  
Нужны соседние элементы `p[i-1]` и `p[i+1]`.  
Используется обмен “ореолом” (halo exchange) с соседними процессами:
- левый ghost-элемент (перед локальным блоком)
- правый ghost-элемент (после локального блока)
Реализуется через `MPI_Sendrecv`.

**Variant 2 (центросимметричная)**  
Нужен элемент `p[N-1-i]`, который может лежать на любом процессе.  
Поэтому собирается полный вектор `p` на каждом процессе:
- `MPI_Allgatherv(local_p -> global_p)`
и затем локально считается:
- `(A*p)[i] = 3*p[i] - p[N-1-i]` (если `N-1-i != i`)

### 4.2 Скалярные произведения

- локально: `sum += a[i]*b[i]`
- глобально: `MPI_Allreduce(sum, SUM)`

### 5.2 Краевые случаи

Проверяются следующие ситуации:

- `N <= 0` — некорректный размер системы (валидация должна возвращать `false`).
- `V < 0` или `V > 2` — некорректный вариант генерации матрицы.
- `N = 1` — минимальный допустимый размер системы.
- `world_size > N` — число MPI-процессов больше размера системы: часть процессов может получить `local_rows = 0`, при этом алгоритм должен корректно работать (коммуникации и редукции остаются корректными).

## 7. Результаты и обсуждение

### 7.1 Корректность

Корректность решения проверяется функциональными тестами. Для полученного вектора `x` вычисляется `A*x` (без хранения полной матрицы — по формулам выбранного варианта) и сравнивается с правой частью `b`, где `b[i] = 1.0`.

В качестве критерия используется максимальное отклонение по компонентам:

- `max_i |(A*x)[i] - 1.0| < 1e-6`

Для MPI-реализации итоговый вектор решения собирается на процессе `rank 0`, и проверка выполняется только на нём. Набор тестов включает несколько размеров `N` и все варианты генерации матрицы (`V = 0..2`), а также отдельные проверки некорректного ввода и минимального случая `N = 1`.


### 7.2 Производительность

Производительные тесты измеряют время выполнения алгоритма в режимах `pipeline` и `task_run` для SEQ и MPI реализаций.

* Эффективность = (Ускорение / P) * 100%
