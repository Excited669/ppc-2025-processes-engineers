## 1. Введение
В работе реализованы два варианта решения системы линейных уравнений, заданной расширенной матрицей в ленточной форме (band matrix): последовательный (SEQ) и вариант для распределённой среды (MPI). Цель работы — реализовать алгоритм, подтвердить корректность через функциональные тесты и выполнить замеры производительности (performance tests).

## 2. Постановка задачи
Дана система линейных уравнений размера n в виде расширенной матрицы n × (n+1), где ненулевые элементы расположены в полосе ширины bandwidth вокруг диагонали. Требуется найти вектор неизвестных x методом Гаусса с выбором опорного элемента по столбцу, при этом использовать ленточную структуру для ограничения операций.

Вход: структура GaussBandInput с полями:

* n — размер системы
* bandwidth — ширина полосы
* augmented_matrix — расширенная матрица в виде одномерного массива

Выход: OutType — вектор решения длины n

## 3. Базовый алгоритм (последовательный, SEQ)

Последовательная версия реализует модифицированный метод Гаусса для ленточной матрицы:

1. Выбор опорного элемента (частичный pivoting) по текущему столбцу i, но поиск ограничен строками в пределах полосы.
2. Перестановка строк при необходимости (в пределах затрагиваемых столбцов полосы).
3. Прямой ход: зануление элементов ниже диагонали только там, где это имеет смысл для полосы.
4. Обратная подстановка: вычисление решения справа налево также с ограничением суммы диапазоном полосы.

Оценка сложности: при узкой полосе стоимость близка к O(n · bandwidth²) (или O(n · bandwidth) для упрощённых вариантов обновления), что существенно дешевле, чем O(n³) для плотной матрицы.

Ограничения: частичный выбор опорного элемента, ограниченный полосой, может быть менее устойчивым, чем полный pivoting по всей матрице. Также эффективность падает при широкой полосе (приближение к плотной матрице).

## 4. Схема распараллеливания

Параллельная версия в задаче peryashkin_v_gauss_vstrip (MPI) выполнена в рамках MPI-интерфейса курса: используется MPI_COMM_WORLD, а результат решения формируется на главном процессе и затем распространяется всем процессам. Это обеспечивает корректную работу под mpirun и совместимость с тестовой инфраструктурой, а также гарантирует одинаковый OutType на всех рангах.

Организация вычислений и обменов данными:

* На каждом процессе определяется rank через MPI_Comm_rank.
* Главный процесс (rank = 0) выполняет весь алгоритм решения ленточной СЛАУ методом Гаусса (прямой ход + обратная подстановка) над входной расширенной матрицей.
* Параметр n рассылается всем процессам с помощью MPI_Bcast, чтобы процессы могли корректно подготовить буферы под результат.
* После вычисления на rank = 0 передаётся флаг успешности (решение найдено / система вырождена) всем процессам через MPI_Bcast. Если флаг неуспеха — задача корректно завершает выполнение.
* Затем вектор решения x рассылается всем процессам через MPI_Bcast, и каждый процесс получает одинаковый результат.

Прямой ход (forward elimination) на rank 0:

* Для каждого столбца i выбирается опорный элемент (pivot) с поиском в пределах полосы bandwidth.
* При необходимости выполняется перестановка строк в расширенной матрице (также ограниченная полосой).
* Для строк ниже текущей выполняется исключение (обнуление элементов под диагональю) только в диапазоне столбцов, попадающих в полосу, что уменьшает объём вычислений относительно плотного случая.

Обратный ход (back substitution) на rank 0:

* Решение вычисляется с конца (i = n-1 ... 0), причём суммирование выполняется только по столбцам в пределах полосы bandwidth.
* Полученное значение x[i] сохраняется в итоговый вектор решения.

### 7.2 Performance тесты

Замеры производительности выполнялись для ppc_perf_tests при числе процессов P = 1, 2, 4:

* Ускорение: Speedup = T_seq / T_parallel

* Эффективность: Efficiency = Speedup / Count * 100%

* task_run — “чистое” время выполнения задачи

В полученных замерах MPI-версия показывает замедление относительно SEQ (speedup < 1). Это связано с накладными расходами MPI (запуск процессов, синхронизации, коллективные операции) и особенностями среды выполнения (контейнер/ограничение ресурсов), из-за чего при данных размерах задачи время коммуникаций и синхронизаций доминирует над полезными вычислениями. При малой вычислительной нагрузке параллелизация может не давать ускорения и даже ухудшать время выполнения, что и наблюдается в таблицах.
